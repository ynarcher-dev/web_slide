## 1. 슬라이드 유형 추가

적용일: 2026-08-27

### 기준

초기 기획은 템플릿을 표지와 본문 둘로 잡았고, 본문의 콘텐츠 영역에는 웹페이지(iframe)만 들어갔다.
개발 스택 문서는 "현재 확정된 MVP에는 사용자 이미지 업로드가 없다"라고 적어 Storage 버킷을 두지 않기로 했다.

### 바뀐 내용

본문 계열에 **이미지**와 **HTML** 두 유형을 추가했다. 템플릿 값은 네 가지가 되었다.

| 템플릿    | 레이아웃 | 콘텐츠 영역에 들어가는 것 |
| --------- | -------- | ------------------------- |
| `cover`   | 표지     | 없음. 흰 배경 + tint      |
| `content` | 본문     | URL을 띄운 iframe         |
| `image`   | 본문     | 사용자가 올린 그림        |
| `html`    | 본문     | 붙여 넣은 HTML (샌드박스) |

세 본문 유형은 같은 레이아웃(페이지명, 대제목, 소제목, 로고, 푸터, 페이지 번호)을 그대로 쓴다.
가운데 16:9 영역에 무엇을 넣는지만 다르다. 렌더러도 본문 렌더러 하나를 공유하고 콘텐츠 영역만 갈라진다.

### 왜 필요했나

- 시연할 웹페이지가 없는 장표(구성도, 캡처, 요약)를 만들 방법이 없었다.
- 그런 장표를 만들려고 외부 도구로 그린 뒤 다시 붙이는 흐름은 "한 도구 안에서 발표를 만든다"는 제품 목표와 어긋난다.
- HTML 유형은 [HTML 슬라이드 작성 프롬프트](html-slide-prompt.md)로 만든 장표를 그대로 붙여 넣기 위한 것이다.

### 구현 경계

**이미지**

- `slide-images` 버킷에 프레젠테이션별 폴더로 저장한다. DB에는 객체 경로만 남긴다.
- PNG, JPEG, WEBP, GIF를 10MB까지 받는다. 값은 `src/lib/supabase/storage.ts`에 있다.
- 버킷은 공개 읽기다. 공유 화면과 서버 PDF가 로그인 없이 이미지를 읽어야 하기 때문이다.
  쓰기와 삭제는 `storage.objects` 정책으로 소유자에게만 열고, 파일명은 무작위로 만든다.
- 슬라이드나 프레젠테이션을 지우면 쓰지 않게 된 파일도 함께 지운다.

**HTML**

- `sandbox="allow-scripts"` iframe의 `srcdoc`으로 그린다. `allow-same-origin`을 함께 주지 않는다.
  같은 출처가 아니므로 붙여 넣은 스크립트가 돌아도 서비스의 쿠키나 DOM에는 닿지 못한다.
- 붙여 넣을 수 있는 길이는 100,000자다.
- 발표 중 조작은 웹페이지 유형과 같은 방식으로 켜고 끈다.

### 반영 위치

- 마이그레이션: `supabase/migrations/20260827120000_slide_image.sql`,
  `20260827130000_slide_image_select.sql`, `20260827140000_slide_html.sql`
- 타입: `slide_template` enum, `slides.image_path`, `slides.html_content`
- 검증: `pnpm db:verify-rls`의 Storage 정책 4건, `e2e/image-slide.spec.ts`, `e2e/html-slide.spec.ts`

### 남은 판단

- 공개 버킷을 비공개 버킷 + 서명 URL로 바꿀지. 공유 화면과 서버 PDF가 걸림돌이다.
- 붙여 넣은 HTML의 허용 태그를 검사할지. 지금은 검사하지 않고 샌드박스에만 의존한다.

## 2. 발표 리모컨 위치 변경

적용일: 2026-08-27

### 기준

초기 기획의 포커스 처리 항목은 두 가지 이동 수단을 함께 두었다.
슬라이드 좌우 가장자리의 이전·다음 버튼과, 화면 아래에 늘 떠 있는 발표 컨트롤이다.
발표 화면은 편집·PDF와 같이 16:9를 유지했다.

### 바뀐 내용

이동 수단을 **화면 위쪽에 접혀 있는 리모컨 하나**로 모았다.

- 좌우 가장자리 이동 버튼을 없앴다.
- 하단 상시 표시 컨트롤을 상단으로 옮기고 평소에는 접어 둔다.
- 리모컨이 비운 자리만큼 슬라이드의 콘텐츠 영역을 넓혔다.
- 전체화면일 때만 16:9 잠금과 여백을 풀어 화면을 가로세로 100%로 채운다.
- 콘텐츠를 조작하는 동안 프레임 테두리를 초록색으로 바꿔 상태를 보여 준다.
- 콘텐츠 영역을 눌러 조작을 켜고, 그 바깥을 눌러 끈다. ESC와 리모컨 버튼도 그대로 쓸 수 있다.

### 왜 필요했나

- 발표 화면에서 가장 중요한 것은 콘텐츠 영역의 크기다. 가장자리 버튼과 하단 바가 그 자리를 상시로 차지했다.
- 가장자리 버튼은 웹페이지를 조작하는 동안 어차피 눌리지 않는다. 클릭이 iframe으로 들어가기 때문이다.
- 발표 장비가 16:9가 아니면 검은 여백이 크게 남았다.

### 구현 경계

- 리모컨이 내려오는 조건은 셋이다. 발표 시작 직후의 첫 노출, 포인터가 화면 위쪽 구역에 있을 때,
  그리고 `:focus-within`이다. 앞의 둘은 `useControlsReveal`이, 마지막은 CSS가 처리한다.
- 바깥 층은 클릭을 받지 않고 안쪽 패널만 받는다. 접힌 층이 슬라이드 클릭을 가로채면 조작을 켤 수 없다.
- 조작 중에는 포인터 이벤트가 iframe으로 들어가 훅에 닿지 않지만, 마우스를 화면 위로 빼면 다시 내려온다.
- 조작을 켜는 덮개는 포커스를 받지 않는 클릭 영역이다. 슬라이드가 `role="img"`라 안쪽에 버튼을 두면
  접근성 검사의 `nested-interactive`에 걸린다. 키보드 사용자는 리모컨의 전환 버튼과 ESC를 쓴다.

### 반영 위치

- `src/features/slide-player/components/presentation-controls.tsx`
- `src/features/slide-player/components/player.module.css`
- `src/features/slide-player/hooks/use-controls-reveal.ts`
- E2E는 `e2e/helpers.ts`의 `revealPlayerControls`로 리모컨을 먼저 내려 놓고 조작한다.

### 남은 판단

- 리모컨이 접혀 있어 처음 쓰는 사람이 못 찾을 수 있다. 첫 노출만으로 충분한지,
  상단에 얇은 손잡이 표시가 필요한지 실제 사용 후 정한다.
- 16:10이나 21:9 화면에서 늘어난 글자가 거슬리는지 확인하고,
  필요하면 채우기와 여백 유지 중 고를 수 있게 할지 정한다.
