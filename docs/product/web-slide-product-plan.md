# Web Slide 제품 기획서

> 문서 상태: 아이데이션 및 MVP 범위 정의  
> 작성일: 2026-08-26  
> 다음 단계: 개발 스택 및 시스템 아키텍처 선정

## 1. 제품 개요

### 1.1 서비스명

**Web Slide**

### 1.2 한 줄 정의

Web Slide는 정해진 슬라이드 템플릿 안에 실제 웹페이지를 삽입하여, 설명과 실시간 제품 시연을 하나의 발표 흐름에서 진행할 수 있게 하는 웹 기반 프레젠테이션 서비스다.

### 1.3 해결하려는 문제

기존 PDF와 PPTX 프레젠테이션은 웹 제품을 정적인 이미지나 링크로만 표현한다. 발표자가 실제 제품을 시연하려면 프레젠테이션을 벗어나 브라우저 탭을 전환해야 하므로 발표 흐름이 끊기고, 화면 전환 과정에서 실수가 발생하기 쉽다.

Web Slide는 프레젠테이션 슬라이드 안에 웹페이지를 직접 표시하고 조작할 수 있게 하여 이러한 단절을 줄인다.

## 2. 제품 목표와 원칙

### 2.1 목표

- 슬라이드 설명과 웹 제품 시연을 하나의 발표 화면에서 제공한다.
- 사용자가 디자인을 직접 구성하지 않아도 일관된 결과물을 만들 수 있게 한다.
- 웹 프레젠테이션을 링크로 공유하고, 필요한 경우 PDF로 내보낼 수 있게 한다.
- 편집 기능을 최소화하여 발표 자료 제작 시간을 줄인다.

### 2.2 제품 원칙

- 범용 PowerPoint 편집기를 만들지 않는다.
- 표지와 본문 템플릿만 제공한다. 본문은 콘텐츠 유형(웹페이지, 이미지, HTML)만 다르고 배치는 같다.
- 드래그 기반 자유 배치보다 정해진 입력 필드와 자동 레이아웃을 우선한다.
- 웹페이지 콘텐츠는 항상 16:9 비율로 표시한다.
- 편집 화면, 발표 화면, PDF 결과물의 시각적 일관성을 유지한다.
- iframe 웹 연동이 가능한 웹페이지 사용을 서비스의 전제 조건으로 한다.

## 3. 주요 사용 시나리오

1. 사용자가 새 프레젠테이션을 생성한다.
2. 브랜드 컬러, 표지 배경 tint, 푸터 등 공통 스타일을 설정한다.
3. 슬라이드 목록에서 표지 또는 본문 슬라이드를 만든다.
4. 만들어진 슬라이드를 선택하여 수정하거나 필요 없는 슬라이드를 삭제한다.
5. 본문 슬라이드에 페이지명, 제목, 소제목을 입력한다.
6. 본문 콘텐츠로 웹페이지 URL을 지정한다.
7. 발표 모드에서 슬라이드를 넘기다가 삽입된 웹페이지를 직접 조작해 제품을 시연한다.
8. 발표 자료를 공유 링크로 전달하거나 PDF로 내보낸다.

## 4. 템플릿 구성

### 4.1 표지 템플릿

표지 템플릿은 프레젠테이션의 시작 페이지로 사용한다.

필수 또는 선택 입력 항목:

- 프레젠테이션 제목
- 발표자 이름
- 고정 서비스 로고
- 흰색 기반 배경 tint

표지에는 배경 이미지 업로드 기능을 제공하지 않는다. 배경은 흰색을 기준으로 하며 사용자는 제한된 범위에서 tint 값만 조절한다.

### 4.2 본문 템플릿

본문 템플릿은 모든 설명 및 시연 페이지에 공통으로 사용한다.

구성 요소:

- 페이지명: 슬라이드 상단의 작은 섹션명
- 대제목
- 소제목
- 로고
- 16:9 메인 콘텐츠 영역
- 푸터 텍스트
- 페이지 번호

개념적 레이아웃:

```text
┌──────────────────────────────────────────────────┐
│ 페이지명                                    로고 │
│ 대제목                                           │
│ 소제목                                           │
│                                                  │
│   ┌──────────────────────────────────────────┐   │
│   │                                          │   │
│   │         16:9 메인 콘텐츠 영역           │   │
│   │                웹페이지                  │   │
│   │                                          │   │
│   └──────────────────────────────────────────┘   │
│                                                  │
│ 푸터 텍스트                           페이지 번호│
└──────────────────────────────────────────────────┘
```

## 5. 메인 콘텐츠 영역

### 5.1 기본 규칙

- 콘텐츠 영역의 비율은 16:9로 고정한다.
- 사용자가 콘텐츠 영역의 위치나 비율을 임의로 변경하는 기능은 제공하지 않는다.
- 템플릿이 제목과 푸터 높이를 고려하여 콘텐츠 영역의 크기와 위치를 자동 계산한다.
- 초기 기준 웹 뷰포트는 1920×1080으로 설정한다.
- 실제 표시 크기에 맞춰 기준 뷰포트를 비율대로 축소한다.

### 5.2 콘텐츠 유형

콘텐츠 영역에는 웹페이지, 이미지, HTML 세 유형 중 하나가 들어간다.
세 유형은 같은 본문 레이아웃(페이지명, 대제목, 소제목, 로고, 푸터, 페이지 번호)을 그대로 쓰고
가운데 16:9 영역에 무엇을 넣는지만 다르다.

#### 웹페이지

- 사용자가 입력한 URL을 iframe으로 표시한다.
- 발표 중 iframe 내부의 버튼, 입력창 등과 상호작용할 수 있다.
- 슬라이드 진입 시 새로고침 여부를 선택할 수 있다.
- iframe 삽입이 허용된 URL만 사용하는 것을 전제로 한다.

#### 이미지

- 사용자가 올린 이미지를 표시한다. PNG, JPG, WEBP, GIF를 10MB까지 받는다.
- 이미지는 잘리지 않게 16:9 영역 안에 맞춘다. 남는 자리는 흰 배경이 된다.
- 파일은 Supabase Storage의 `slide-images` 버킷에 프레젠테이션별 폴더로 저장한다.
- 쓰기 권한은 프레젠테이션 소유자로 제한하고, 파일명은 추측할 수 없는 무작위 값을 쓴다.
- 조작할 대상이 없으므로 발표 중 상호작용 전환도 없다.

#### HTML

- 사용자가 붙여 넣은 HTML을 그대로 표시한다. 별도 주소나 파일이 필요 없다.
- 격리된 iframe(`sandbox="allow-scripts"`, 같은 출처 아님) 안에서 그린다.
  붙여 넣은 스크립트는 동작하지만 서비스의 세션이나 화면에는 접근하지 못한다.
- 발표 중에는 웹페이지 유형과 같은 방식으로 조작을 켜고 끌 수 있다.

## 6. 프레젠테이션 공통 설정

슬라이드별 반복 입력을 줄이기 위해 다음 항목은 프레젠테이션 단위로 관리한다.

- 고정 서비스 로고
- 브랜드 대표 색상
- 표지 배경 tint
- 기본 글꼴
- 기본 푸터 텍스트
- 페이지 번호 표시 여부

로고는 사용자가 업로드하거나 변경하지 않으며, 첨부된 Y&ARCHER 로고를 애플리케이션의 정적 자산으로 포함한다. 본문 슬라이드는 공통 설정을 기본으로 상속한다. MVP 이후 필요성이 확인되면 특정 슬라이드에서만 값을 덮어쓰는 기능을 추가한다.

## 7. 편집 화면

편집기는 다음 세 영역으로 구성한다.

```text
┌──────────────┬──────────────────────────┬──────────────┐
│ 슬라이드 목록 │       16:9 미리보기      │  속성 패널   │
│              │                          │              │
│ + 표지       │                          │ 페이지명     │
│ + 본문       │                          │ 대제목       │
│              │                          │ 소제목       │
│              │                          │ 콘텐츠 설정  │
└──────────────┴──────────────────────────┴──────────────┘
```

필수 편집 기능:

- 표지 또는 본문 슬라이드 추가
- 슬라이드 삭제
- 드래그를 통한 슬라이드 순서 변경
- 입력 필드 기반 콘텐츠 수정
- 웹페이지 URL 입력
- 슬라이드 미리보기
- 프레젠테이션 공통 설정

자유로운 요소 생성, 도형 그리기, 개별 요소 리사이즈 기능은 MVP에서 제외한다.

### 7.1 슬라이드 관리

프레젠테이션 편집 화면의 왼쪽 패널에서 슬라이드를 관리한다. 별도의 복잡한 관리 도구를 두지 않고, 목록과 기본 CRUD 기능만 제공한다.

#### 슬라이드 만들기

- `슬라이드 추가` 버튼을 누르면 표지, 본문, 이미지, HTML 중 하나를 선택한다.
  본문, 이미지, HTML은 같은 본문 레이아웃을 쓰고 가운데 콘텐츠 영역에 무엇이 들어가는지만 다르다.
- 새 슬라이드는 기본적으로 현재 선택한 슬라이드 다음에 생성한다.
- 프레젠테이션에는 표지 슬라이드를 여러 개 만들 수 있지만, 첫 슬라이드에 표지를 사용하는 것을 기본 흐름으로 안내한다.
- 새 본문 슬라이드는 빈 제목과 빈 콘텐츠 상태로 생성한 뒤 바로 편집 화면을 연다.

#### 슬라이드 리스트

각 목록 항목에 다음 정보를 표시한다.

- 자동으로 계산된 페이지 번호
- 슬라이드 미리보기 썸네일
- 페이지명 또는 대제목
- 템플릿 유형: 표지, 본문, 이미지, HTML
- 현재 선택 상태

목록에서는 슬라이드 선택과 드래그 순서 변경을 지원한다. 순서가 변경되면 페이지 번호도 자동으로 다시 계산한다.

#### 슬라이드 수정

- 목록에서 슬라이드를 선택하면 중앙 미리보기와 오른쪽 속성 패널에 해당 데이터가 열린다.
- 입력값 변경 내용은 자동 저장하는 것을 기본 동작으로 한다.
- 저장 중, 저장 완료, 저장 실패 상태를 사용자에게 표시한다.

#### 슬라이드 삭제

- 목록 항목의 메뉴 또는 속성 패널에서 삭제할 수 있다.
- 실수 방지를 위해 삭제 전에 확인한다.
- 현재 선택한 슬라이드를 삭제하면 인접한 슬라이드를 자동으로 선택한다.
- 마지막 슬라이드를 삭제한 경우 빈 상태와 `슬라이드 추가` 버튼을 표시한다.

#### 빈 상태

프레젠테이션에 슬라이드가 없으면 다음 행동을 제공한다.

- 표지 슬라이드 만들기
- 본문 슬라이드 만들기

## 8. 발표 모드

### 8.1 기본 기능

- 브라우저 전체화면 발표
- 이전 및 다음 슬라이드 이동
- 키보드와 발표 리모컨을 통한 탐색
- 웹페이지 조작 모드와 슬라이드 탐색 모드 구분
- 현재 페이지와 전체 페이지 표시
- 공유용 읽기 전용 URL

편집, 공유 화면과 PDF는 16:9를 지킨다. 전체화면 발표만 예외로 슬라이드를 화면 가로세로 100%로 채운다.
발표 장비의 화면 비율이 16:9가 아니면 검은 여백이 남는 대신 슬라이드가 그만큼 늘어난다.

### 8.2 발표 리모컨

이전, 다음, 페이지 표시, 조작 모드 전환, 전체화면과 발표 종료는 하나의 리모컨에 모아 둔다.
리모컨은 화면 위쪽 가운데에 접혀 있다가 필요할 때만 내려온다.

- 발표를 시작하면 위치를 알 수 있도록 잠깐 보여 준 뒤 접는다.
- 포인터가 화면 위쪽 구역에 들어오면 다시 내려온다.
- 키보드 포커스가 리모컨 안으로 들어와도 내려온다.
- 접혀 있는 동안에는 슬라이드 클릭을 가로채지 않는다.
- 리모컨이 비운 자리만큼 슬라이드의 콘텐츠 영역을 넓게 쓴다.

슬라이드 좌우 가장자리에는 이동 버튼을 두지 않는다. 콘텐츠 영역을 가리고,
웹페이지를 조작하는 동안에는 어차피 눌러도 클릭이 iframe으로 들어가기 때문이다.

### 8.3 포커스 처리

iframe 내부를 클릭하면 키보드 입력을 웹페이지가 가져갈 수 있다. 따라서 발표 중 슬라이드 이동이 막히지 않도록 다음 장치를 제공한다.

- iframe 바깥에서 언제든 불러낼 수 있는 발표 리모컨
- 웹페이지 조작을 종료하고 슬라이드 탐색으로 돌아오는 명확한 동작.
  콘텐츠 영역 바깥을 누르거나 ESC를 누르거나 리모컨의 전환 버튼을 쓴다.
- 조작 중인 상태를 콘텐츠 영역 테두리 색으로 함께 표시
- 필요 시 웹페이지 상호작용을 잠그는 기능

## 9. PDF 내보내기

### 9.1 기본 원칙

- 한 슬라이드를 PDF 한 페이지로 변환한다.
- 웹 발표 화면과 동일한 16:9 레이아웃을 유지한다.
- 표지, 제목, 로고, 푸터와 페이지 번호를 포함한다.

### 9.2 웹페이지 콘텐츠 처리

PDF에서는 웹페이지를 직접 조작할 수 없으므로 정적인 이미지로 변환한다.

- 웹페이지의 대표 화면 또는 현재 화면을 캡처한다.
- 캡처 이미지를 16:9 콘텐츠 영역에 삽입한다.
- 캡처 영역에 원본 웹페이지 URL을 클릭 가능한 링크로 연결한다.
- 향후 선택 기능으로 QR 코드를 추가할 수 있다.

### 9.3 예상 제약

- 로그인이 필요한 페이지는 서버 측 자동 캡처가 어려울 수 있다.
- 사용자 브라우저나 사내 네트워크에서만 접근 가능한 페이지는 자동 캡처할 수 없다.
- 동영상, 애니메이션과 실시간 데이터는 PDF에 정지 화면으로만 표현된다.

## 10. 웹페이지 삽입 제약

모든 외부 웹사이트를 iframe으로 표시할 수 있는 것은 아니다.

- 대상 서버가 `X-Frame-Options` 또는 CSP `frame-ancestors`로 삽입을 차단할 수 있다.
- 다른 도메인의 웹페이지 내부 DOM은 동일 출처 정책으로 인해 Web Slide가 직접 제어할 수 없다.
- 로그인 쿠키, 카메라, 마이크, 클립보드 등은 브라우저 정책에 따라 iframe에서 제한될 수 있다.

따라서 초기 제품의 지원 범위는 다음과 같이 정의한다.

> 사용자가 소유하거나 iframe 삽입이 명시적으로 허용된 웹페이지를 프레젠테이션에 포함한다.

사용자가 직접 관리하는 웹페이지와의 고급 연동은 `window.postMessage` 기반으로 확장할 수 있다.

## 11. MVP 기능 범위

### 포함

1. 사용자 프레젠테이션 생성 및 저장
2. 표지와 본문 템플릿
3. 슬라이드 만들기, 목록 조회, 수정, 삭제 및 순서 변경
4. 정해진 텍스트 필드 편집
5. 공통 로고, 브랜드 색상 및 푸터 설정
6. 16:9 콘텐츠 영역. 웹페이지, 이미지, 붙여 넣은 HTML 세 유형을 지원한다
7. 전체화면 발표 모드
8. 읽기 전용 공유 링크
9. PDF 내보내기
10. 자동 페이지 번호

### 제외

- PPTX 내보내기
- 자유 배치형 캔버스 편집
- 도형, 차트 및 표 편집 도구
- 실시간 공동 편집
- 댓글과 승인 워크플로
- 복잡한 전환 효과 및 애니메이션
- 임의 템플릿 제작 도구
- iframe 삽입 제한 우회

## 13. 성공 기준

MVP는 다음 조건을 만족하면 핵심 가설을 검증한 것으로 본다.

- 사용자가 별도의 사용 설명 없이 표지와 본문 슬라이드를 만들 수 있다.
- 사용자가 슬라이드 목록에서 원하는 슬라이드를 찾고 수정하거나 삭제할 수 있다.
- 웹페이지가 포함된 발표를 슬라이드 흐름을 벗어나지 않고 진행할 수 있다.
- 편집 화면과 발표 화면에서 레이아웃이 동일하게 유지된다.
- 웹페이지를 포함한 자료를 읽을 수 있는 형태로 PDF 변환할 수 있다.
- 지원 대상으로 등록된 웹페이지가 발표 모드에서 정상적으로 로드되고 조작된다.
